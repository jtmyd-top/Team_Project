   ## 1. 变更背景

   在 V2.0 基础上，为了应对潜在的暴力破解（Brute Force）攻击，避免海量失败日志淹没管理员视野。

   **目标**：将散乱的失败日志聚合成高价值的“安全事件”。例如：*“检测到 IP 192.168.1.5 尝试登录 Admin 账户失败 58 次”*。

   ## 4. 技术实现方案 (Implementation Guide)

   为了实现这个功能，后端不需要返回几千条日志，而是直接返回“统计结果”。

   ### 4.1 后端 API (Django) - 聚合逻辑

   修改 `dashboard_stats_api` 中的 `vault_alerts` 部分，使用 Django ORM 的 `annotate` 进行聚合：

   Python
   
   ```
   from django.db.models import Count, Max
   from django.utils import timezone
   from datetime import timedelta
   
   # ... 在 dashboard_stats_api 视图中 ...
   
   if section in ['vault_alerts', 'all']:
       # 1. 设定时间窗口：例如只看最近 1 小时内的失败记录
       time_threshold = timezone.now() - timedelta(hours=1)
       
       # 2. 聚合查询：按 'user' 和 'ip_address' 分组，统计次数
       # 假设您的日志模型叫 AccessLog，失败状态为 status=False
       # 如果是用 Django Admin LogEntry，可能需要解析 message 字段，或者您有自定义的 LoginAttempt 模型
       
       alerts_queryset = AccessLog.objects.filter(
           status=False, 
           timestamp__gte=time_threshold
       ).values('user__username', 'ip_address').annotate(
           failure_count=Count('id'),
           last_attempt=Max('timestamp')
       ).filter(failure_count__gt=0).order_by('-failure_count') # 按次数降序排列
   
       # 3. 格式化输出
       alerts_data = []
       for item in alerts_queryset:
           alerts_data.append({
               'user': item['user__username'] or 'Unknown',
               'ip': item['ip_address'],
               'count': item['failure_count'],  # 🔥 新增：次数
               'time': item['last_attempt'].strftime('%H:%M:%S'),
               # 动态计算严重等级
               'level': 'critical' if item['failure_count'] > 10 else 'warning'
           })
           
       data['vault_alerts'] = alerts_data
   ```

   ### 5. 验收标准 (V2.1)
   
   1. **聚合验证**：在后台模拟同一 IP 连续输入 5 次错误密码。
   2. **大屏表现**：战情室的“保密柜告警”区域不应出现 5 行记录，而应出现 **1 行记录**。
   3. **数据显示**：该记录显示 `用户: admin`, `IP: 127.0.0.1`, `次数: 5`。
   4. **性能验证**：即使数据库中有 1 万条失败日志，接口响应时间应在 200ms 以内（依赖后端 `Count` 聚合而非 Python 循环）。
