## 1. 项目背景与目标

系统已具备基础的硬件与业务监控能力。为满足生产环境对“安全审计”和“故障排查”的严苛要求，V2.3 版本将进行底层架构升级：

1. **数据持久化**：从“Redis 缓存/实时流”模式切换为 **“数据库回溯”** 模式。确保管理员即使隔天查看大屏，也能看到过去 24 小时内的聚合告警和系统操作历史。
2. **交互闭环**：战情室作为“信号层”，必须能通过点击跳转（Drill-down）至 Django Admin “数据层”，实现从发现问题到解决问题的闭环。
3. **自适应安全**：引入“信任设备”机制，平衡 2FA 的安全性与用户体验，并实施多维度的风控拦截。

------

## 2. 核心功能模块 (Functional Requirements)

### 2.3 安全态势感知 (Security & Vault Alerts) - 核心升级 🔥

*目标：持久化记录攻击行为，通过聚合降低噪点，提供主动防御能力。*

- **暴力破解聚合 (Aggregation)**:
  - **逻辑**: 按 `用户 + IP` 维度聚合最近 **24小时** 内的失败尝试。
  - **持久化**: 数据源由 Redis 改为数据库 `AccessLog` 表，重启不丢失。
  - **展示**:
    - 紧凑列表模式 (Compact Mode)。
    - 显示：`用户名` | `IP (等宽字体)` | `24h内失败次数` | `严重度色条`。
- **主动防御 (Active Defense)**:
  - **封禁 IP**: 在告警条目上提供 **[BAN]** 按钮，点击后将 IP 加入黑名单。
  - **跳转审计**: 点击告警条目，跳转 Admin 的 `AccessLog` 列表，并自动过滤该 IP。

### 2.4 系统日志流 (System Logs) - 历史回填

*目标：提供黑客帝国风格的实时日志，并支持历史回溯。*

- **历史回填 (Backfill)**:
  - 页面加载时，自动从数据库 (`django_admin_log`) 读取最近 **10条** 操作记录填补空白。
  - 后续增量通过轮询/推送更新。
- **视觉风格**: Matrix 终端风格，红/绿/黄高亮区分 增/删/改 操作。
- **交互**: 点击标题跳转 Admin 全量日志页面。

## 3. 信任设备与 2FA 风控 (Trusted Device Security) - 新增 🔥

### 3.1 业务流程

- **登录时**: 用户通过 2FA 验证后，可勾选 **“信任此浏览器 30 天”**。
- **再次登录**:
  - 若设备 Cookie 有效且未过期 -> **跳过 2FA**。
  - 若设备未知或过期 -> **强制 2FA**。
- **有效期策略**: **滚动续期 (Sliding Window)**。每次成功登录自动顺延 30 天，保证活跃用户体验。

### 3.2 风险控制策略 (Defense Strategy)

为防止“滚动续期”带来的安全风险，实施 **三级风控计数器**：

| **维度**            | **阈值 (示例)** | **惩罚措施**       | **目的**                                     |
| ------------------- | --------------- | ------------------ | -------------------------------------------- |
| **设备级 (Device)** | 3 次失败        | **失效该设备信任** | 阻断单一被盗设备的攻击，不影响用户其他设备。 |
| **用户级 (Global)** | 5 次失败        | **冻结账户**       | 防止攻击者利用多设备分布式撞库。             |
| **IP 级 (Network)** | 10 次失败       | **封禁 IP**        | 防止僵尸网络攻击。                           |

- **敏感操作熔断**: 即使是信任设备，进入“保密柜”或“修改密码”时，**必须**再次验证 2FA（Sudo Mode）。

## 4. 数据模型设计 (Database Schema)

### 4.1 安全访问日志 (`AccessLog`)

*用于持久化存储保密柜验证失败记录。*

Python

```
class AccessLog(models.Model):
    user_identifier = models.CharField("用户/账号", max_length=150)
    ip_address = models.GenericIPAddressField("来源IP")
    action = models.CharField("行为", choices=(('vault_fail', '保密柜失败'), ...))
    count = models.IntegerField("聚合频次", default=1)
    details = models.TextField("详细信息")
    created_at = models.DateTimeField("发生时间", auto_now_add=True)
```

### 4.2 信任设备 (`TrustedDevice`)

*用于管理免 2FA 的设备令牌。*

Python

```
class TrustedDevice(models.Model):
    user = models.ForeignKey(User, ...)
    device_token = models.CharField("加密令牌", unique=True) # 存入 Cookie
    user_agent = models.CharField("UA标识")
    ip_address = models.GenericIPAddressField("首次IP")
    last_login_ip = models.GenericIPAddressField("最近IP")
    expires_at = models.DateTimeField("过期时间") # 滚动更新
```

## 5. UI/UX 设计规范

- **主题**: 深色赛博朋克 (Cyberpunk Dark)。
- **布局**: 三栏式栅格布局 (响应式)。
- **交互细节**:
  - **可点击元素**: 鼠标悬停显示光晕 (Glow) + 上浮动画，鼠标指针变为手型。
  - **时间显示**: 历史数据必须包含日期 (如 `02-07 14:30`)。
  - **加载状态**: 数据加载期间显示骨架屏 (Skeleton)，网络断开显示顶部红色重连倒计时。

## 6. 技术实现要点

1. **后端 (Django Views)**:
   - `dashboard_stats_api`: 改造为 ORM 查询。
     - `vault_alerts`: 查询 `AccessLog`，过滤 `now() - 24h`，按 `user+ip` Group By。
     - `system_logs`: 查询 `LogEntry`，`order_by('-action_time')[:10]`。
   - `login_view`: 增加 Cookie 校验逻辑，写入/读取 `trust_device_token`。
2. **前端 (Vue 3)**:
   - `VaultAlertPanel`: 适配新的 `time` 字段显示，绑定点击事件到 `window.open(admin_url)`。
   - `LogTerminal`: 初始化时直接渲染后端返回的 10 条历史日志。
3. **Admin 后台**:
   - `TrustedDeviceAdmin`: 列表显示设备状态。**关键逻辑**：每行只显示该设备 Token 对应的失败次数（不显示用户全局失败次数），实现精准归因。

## 7. 验收标准 (Acceptance Criteria)

1. **持久化验证**: 重启后端服务后，刷新战情室页面，过去 24 小时的保密柜告警和最近 10 条系统日志**必须存在**，且时间显示正确。
2. **信任设备验证**:
   - 勾选信任后，关闭浏览器再打开，登录**不应**出现 2FA 输入框。
   - 在信任设备上输错保密柜密码 3 次，该设备信任**应失效**，且 Admin 后台该设备行显示警告。
3. **钻取验证**: 点击“保密柜告警”中的某条 IP 记录，应新窗口打开 Admin 的 `AccessLog` 列表，且自动应用了该 IP 的过滤器。
