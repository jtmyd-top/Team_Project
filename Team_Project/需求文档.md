# 项目需求文档 (PRD): 系统监控“战情室” (Dashboard Module)

| **文档版本** | **V1.0**                                         |
| ------------ | ------------------------------------------------ |
| **项目名称** | 知识库系统 - 战情室监控模组 (War Room Dashboard) |
| **面向用户** | 超级管理员 (Superuser)                           |
| **技术栈**   | Backend: Django (DRF)                            |

## 1. 项目背景与目标 (Background & Goals)

随着核心业务（笔记、保密柜、回收站）架构重构的完成，系统产生大量业务数据与操作日志。当前缺乏一个全局视角来监控系统运行状态。

**目标**是构建一个集成在后台管理系统中的“战情室”大屏，具备**科技感 (Cyberpunk/Dark UI)**，提供**实时 (Real-time)** 的系统健康度、安全态势及业务数据监控，辅助管理员进行决策与快速排障。

## 2. 核心功能模块 (Functional Requirements)

我们将战情室划分为三个核心监控维度：**基础设施 (Infrastructure)**、**业务指标 (Business Metrics)** 和 **安全态势 (Security Posture)**。

### 2.1 基础设施监控 (Infrastructure Health)

*目标：确保服务器及底层服务稳定运行。*

| **功能点**     | **描述**                                                     | **数据来源/技术方案**                | **优先级** |
| -------------- | ------------------------------------------------------------ | ------------------------------------ | ---------- |
| **服务器心跳** | 实时显示 CPU 使用率、内存占用、磁盘 I/O。                    | Python `psutil` 库 + WebSocket 推送  | P0         |
| **服务状态**   | 监控 Redis (缓存)、Celery (异步任务)、Database (连接数) 状态。 | Django Cache API / Celery Flower API | P1         |
| **异常日志流** | 滚动显示最新的 Django `ERROR` 级别日志。                     | 读取日志文件或 Sentry 集成           | P1         |

### 2.2 业务指标监控 (Business Metrics)

*目标：基于已完成的“笔记管理”等模块，展示系统活跃度。*

| **功能点**           | **描述**                                           | **关联模块**                     | **优先级** |
| -------------------- | -------------------------------------------------- | -------------------------------- | ---------- |
| **知识资产概览**     | 统计卡片：总笔记数、总文件夹数、总附件大小。       | 笔记管理、文件夹树               | P0         |
| **回收站积压**       | 监控回收站内的文件数量及占用空间，预警长期未清理。 | 回收站模块                       | P2         |
| **内容增长趋势**     | 折线图展示近 7/30 天的新增笔记与修改频率。         | 笔记管理 (Created/Modified Time) | P1         |
| **热力图 (Heatmap)** | 展示用户（或管理员）在哪些时间段产出最高。         | 操作日志                         | P2         |

### 2.3 安全态势感知 (Security & Vault Monitor)

*目标：针对“保密柜”等高敏模块进行重点审计。*

| **功能点**       | **描述**                                                     | **关联模块**           | **优先级** |
| ---------------- | ------------------------------------------------------------ | ---------------------- | ---------- |
| **保密柜围栏**   | **核心功能**：实时告警“保密柜”的失败访问尝试或异常高频访问。 | 保密柜模块             | P0         |
| **入侵检测**     | 地图或列表展示登录 IP 分布，标记异常归属地登录。             | 用户认证 (Access Logs) | P1         |
| **敏感操作审计** | 滚动显示敏感操作流（如：永久删除、修改权限、导出数据）。     | Django Admin LogEntry  | P1         |

## 3. UI/UX 设计要求 (UI/UX Requirements)

鉴于“战情室”的定位，界面设计需区别于传统的 CRUD 后台，强调视觉冲击力。

- **设计风格**：深色模式 (Dark Mode)，采用冷色调（青色、深蓝）为主，高亮报警色为霓虹红/橙。
- **布局结构**：
  - **顶部 (Header)**：全局状态（如：系统运行时间 Uptime）、当前时间、天气/地理位置。
  - **左/右侧栏 (Sidebars)**：各类指标图表（ECharts 饼图、雷达图、柱状图）。
  - **中心区域 (Center Stage)**：核心动态视觉元素（如：3D 地球、系统拓扑图或实时滚动的日志流）。
- **交互体验**：
  - **响应式**：适配 1080P 及以上大屏分辨率。
  - **全屏模式**：提供一键全屏按钮，隐藏浏览器边框。
  - **动态效果**：数据加载时的数字滚动动画 (CountUp)，图表的动态刷新效果。

## 4. 技术实现方案 (Technical Implementation)

### 4.1 后端 (Django)

- **API 设计**：使用 Django REST Framework (DRF) 提供只读接口 `GET /api/dashboard/stats/`。
- **实时性**：
  - *方案 A (推荐)*：集成 **Django Channels** (WebSocket)，实现服务器端主动推送 CPU/内存变化及安全告警。
  - *方案 B (轻量)*：前端使用 `setInterval` 每 5-10 秒轮询 API。
- **数据缓存**：对于计算量大的统计（如全站笔记总数、趋势图），使用 Redis 缓存结果，设置 5-10 分钟过期时间，避免频繁查询数据库拖慢生产环境。

### 4.2 前端 (Vue 3)

- **组件化**：
  - `StatCard.vue`: 单一数值展示组件（带环比箭头）。
  - `LiveChart.vue`: 封装 ECharts 逻辑，支持 Resize。
  - `LogStream.vue`: 滚动日志列表组件。
- **图表库**：Apache ECharts 5.0 或 DataV (适合大屏可视化)。
- **样式库**：TailwindCSS (便于快速构建 Grid 布局和深色主题)。

## 5. 验收标准 (Acceptance Criteria)

1. **加载速度**：首屏数据加载时间 < 1秒（依赖缓存策略）。
2. **实时响应**：在后端触发“保密柜访问失败”事件后，大屏需在 2 秒内弹出红色告警。
3. **视觉还原**：在 Windows x64 Chrome 浏览器下，全屏显示无滚动条，布局不崩坏。
4. **无侵入性**：战情室的运行（频繁查询）不得影响核心业务（笔记读写）的数据库性能。
